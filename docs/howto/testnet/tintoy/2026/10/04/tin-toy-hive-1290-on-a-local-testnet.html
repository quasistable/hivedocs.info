Tin Toy - Hive 1.29.0 on a Local Testnet

Oct 4, 2026 • inertia

Your own local testnet

@inertia
Tin Toy has a new core release for Hive 1.29.0. The idea is still the same: a small local testnet for working on Hive applications without broadcasting your experiments to mainnet. There are a couple of changes worth calling out before you copy a command from an older tintoy post. #### The core image The current image starts hived, applies the sample snapshot through Tinman, and sets up 21 deterministic witnesses. RPC is now on port 8092; p2p is on 2001. The old Jussi, nginx, Postgres, Hivemind, condenser, and Tinman-server files are still in the gist as reference material, but those services aren't started or exposed by this image. If your app depends on Hivemind's content APIs, that part of the old stack isn't included in the current core release. #### Try it out With Docker running Linux containers, the README's quick start is: ```bash docker run --rm --platform linux/amd64 --name tintoy \ -p 8092:8092 \ -p 2001:2001 \ inertia/tintoy:1.29.0 ``` Python, Tinman, and Hive are included. The command assumes a Bash-compatible shell, so use WSL or Git Bash on Windows. ARM hosts, including Apple Silicon, need AMD64 emulation. This is a disposable testnet with deterministic keys. Keep it off untrusted networks. For a Docker daemon on your own machine, use `-p 127.0.0.1:8092:8092` and `-p 127.0.0.1:2001:2001` to bind the published ports to localhost. Allow several minutes for bootstrap. Look for this message: ``` tintoy: snapshot applied and seed node is producing ``` Then, from another terminal, check the RPC endpoint. This command uses curl and jq on your host: ```bash curl -sS http://127.0.0.1:8092 \ --data '{"jsonrpc":"2.0","method":"database_api.get_dynamic_global_properties","params":{},"id":1}' \ | jq ``` Run it twice, a few seconds apart. `head_block_number` should increase. #### Which tag? - `1.29.0`: the current Hive 1.29.0 core testnet - `latest`: currently the same 1.29.0 release - `1.28.7`: the Hive 1.28.7 release built for testnet - `core-2026.10.03`: the original dated core release, also using Hive 1.29.0 - `legacy-2021`: the previous May 2021 image, with its historical services and ports One detail about `1.28.7`: its testnet binary reports blockchain version `1.28.6`. That's how the upstream release is defined. The image includes the release's peer-handling fixes; the image tag and the reported blockchain version describe different things. Also, `latest` now points to the core release. An old port-8090 command won't give you the same stack it did in 2021. #### Building from source The current Dockerfile uses pinned Tinman and Hive images. From a checkout of [the gist](https://gist.github.com/inertia186/b88e7bfff8862858e54c59392e2bce20), build with: ```bash docker build --platform linux/amd64 -t tintoy:local . ``` The [README](https://gist.github.com/inertia186/b88e7bfff8862858e54c59392e2bce20#file-readme-md) has the build arguments for trying other image combinations. Use immutable image digests when you need a reproducible result. The documented checks cover the 2,000-account sample, registration and scheduling of all 21 replacement witnesses, and advancing blocks. The current Tinman pin has passed fresh Docker Desktop AMD64-emulation bootstraps with both Hive 1.29.0 and 1.28.7. If you need a little chain to develop against, that's the starting point: bring it up, check that blocks are moving, and point your app at the local RPC endpoint.
