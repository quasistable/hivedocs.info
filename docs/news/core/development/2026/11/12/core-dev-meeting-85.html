Core dev meeting #85

Nov 12, 2026 • howo

Core development meeting recording and an AI-generated summary covering Gopherd, lite accounts, Hivemind, HAF and API work.

@howo
https://www.youtube.com/watch?v=Blvm5pvinHo Hello, here's the core dev meeting of the month. It's been a while, last time we all met in person at HiveFest so there's quite a bit to cover. AI generated summary, some mistakes may have slipped through so please listen to the meeting for the accurate info. # Me (@howo) - Gopherd: mostly unglamorous work now, optimizations, security fixes and getting the experience on par with hived. It's been producing quite a few blocks which is nice. - Floated the idea of a client identifier in the witness version field so voters can see which client a witness runs. Conclusion: since both clients have feature parity there's no real need yet, people can just say it in a post. We'll revisit later. - Two MRs that have been waiting for review for a while: - DHF `daily_pay` overflow: there's no upper bound, so a big enough proposal could overflow and crash the chain during maintenance. It would never get voted in, but no reason to leave it open. It's a hardfork change, so there's no rush. - Moderation audit log on hivemind: a new table logging every mod action (mute, unmute, pin, set role etc.) plus 3 endpoints (log, per account, moderator activity). No perf impact since mod actions are rare. - Side experiment I still want to get to: using hive + HAF as a data availability layer for the OP stack (Optimism) to get EVM compatibility as an L2, no L1 changes needed. # @blocktrades - Release is getting close. Dan estimates the pace is ~10x faster than at the start of the year thanks to AI. - Lite accounts are in testing, with the API up on api.syncad.com. Now is the time to send feedback (good-karma and asgarth are already looking at it). - REST API for hivemind is in. - HAF and all its apps now replay at the same time: a full node with every app (FYP and haf-stats included) replays in under 24h instead of ~2 days. - Big API speedups across HAF apps, especially hivemind and account history (no more timeouts on huge accounts). There's also an option to get discussions without vote data for lighter responses. - Denser: new chat, better proposals page, FYP page, doesn't load wax on every page anymore. The healthchecker component can now pick a different API node per API. - Beekeeper hardening following Gandalf's security feedback. - API node: tracked down slowdowns to a memory/garbage collection issue in drone (rust) and worked around it, and added load shedding against AI scraper bots. GitLab now requires login for non rate limited access. - AI went through all the open issues (43 of Gandalf's got closed in one night), labels were harmonized and old issues/MRs cleaned up. - Experimenting with speeding up hived replay/sync, not sure it'll make the release. # @mcfarhat - HAF FYP and haf-stats are now part of the HAF API node bundle. PeakD and Denser integrated FYP, Ecency is working on it. - FYP algorithm 1.4.1 is the default on a fresh deploy. Weights are configurable per node, the post window went to 48h so less active languages still get content, and storage went from 300GB to ~7.4GB. - haf-stats no longer locks hivemind and now records actual RC costs instead of estimates. - HiveSense: search by author and by time range is on the test API. - Block explorer: light vs full mode via an env var (hivescan.info and classic.hivescan.info), missed blocks and voting power on the witness list, top holders combine liquid + savings, phantom null/steem.dao balances fixed. - Actifit: big security hardening, Fitbit moved to Health Connect, signups in the mobile app. - HiveSense MR !148 has been waiting on CI for a while, Dan will follow up. Also welcome to @acid who joined for the first time!
Source: Core dev meeting #85 by @howo
